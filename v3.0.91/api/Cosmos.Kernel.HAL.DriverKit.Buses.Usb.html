Namespace Cosmos.Kernel.HAL.DriverKit.Buses.Usb

Classes

UsbAccess

The access object of a USB interface node, the one thing a class driver sees: the interface's identity and endpoints, control transfers on the device's default pipe (serialized across the device's interfaces), the pipes it opens on the ledger of its binding, bulk transfers through them, and, for a hub driver, the enumeration core for the hub's ports. One per interface node. Every member is thread context unless its summary says otherwise: a probe, a work item, a driver thread or a ring caller, never an interrupt handler; called from one (a UsbReportHandler on a controller that delivers reports in interrupt context), a member stops with an exception naming itself in a synthetic dispatch, or a panic in a real interrupt, as the binding's members do.

UsbBus

One USB bus: a bound host controller, its 1-based ordinal, the device tree below it and the enumeration core's entry points for root ports. The host driver creates it from its probe and calls Attach(byte, UsbSpeed) and Detach(byte) for root ports from its probe and its hot-plug thread; the hub driver reaches the same core for hub ports through AttachChild(DeviceBinding, byte, UsbSpeed) and DetachChild(DeviceBinding, byte). The tree is guarded by one IRQ-safe lock around list changes only, never across a transfer or a kit call: the host thread and a hub thread change it concurrently. The execution context of each member is in its summary.

UsbClassCode

Base class codes a class driver matches an interface against (usb.org "Defined Class Codes").

UsbDevice

One USB function behind one port: the host created it when it addressed the port (an xHCI slot) and derives from it to carry its per-device state and the transfer primitives; the enumeration core fills the identity it read from the descriptors. A host implements the protected members; the kit calls them through the internal ones, so a class driver holding a reference can reach none of them and goes through its UsbAccess instead.

UsbEndpoint

One endpoint descriptor of an interface (USB 2.0 section 9.6.6), as the enumeration core parsed it. Any context, immutable after parsing.

UsbHostController

The contract a USB host controller driver implements for the kit: how a device on a port gets its address and how its state is freed again. The host driver binds the controller's own node (a PCI function for xHCI), creates a UsbBus over this object from its probe, and owns every register, ring, context and DMA page; the kit never publishes a node for the controller itself. A host implements the protected members; the kit calls them through the internal ones, so a class driver holding a reference can reach neither.

UsbHubProtocol

The protocol numbers of the hub class (USB 2.0 chapter 11, USB 3.2 chapter 10), so a hub driver carries numbers, not a copy of the kit's state machine. Constants; any context.

UsbIdentity

The identity of one interface of a USB device, as the enumeration core read it from the descriptors: where it is (the port path from the host controller down, the interface number), what the device is (vendor, product, device class triplet, speed) and what the interface is (its class triplet). Read once when the device was attached; never changes. Path is usb:<port path>:<interface number>, so a stick on root port 1 of the first controller is usb:1-1:0.

UsbMatch

A match over USB interface identities: every field given must equal the identity's, every field left null is not looked at, and the specificity is the number of fields given. The port path and the speed are identity, not match fields. A match that constrains nothing is refused. So a vendor and product match (2) outranks a class-only match (1) and a full interface triplet (3) outranks both.

UsbPipe

An opened endpoint: an interrupt IN pipe that delivers reports to a UsbReportHandler, or a bulk pipe (IN or OUT) the driver transfers through BulkIn(UsbPipe, Span<byte>, out int) and BulkOut(UsbPipe, ReadOnlySpan<byte>, out int). The host creates it and derives its own pipe kinds from it; the kit records it on the ledger of the binding that opened it and closes it in the unwind, or earlier through ClosePipe(DeviceBinding, UsbPipe). Any context for the two getters.

Structs

UsbSetupPacket

The 8-byte SETUP packet that opens every control transfer (USB 2.0 section 9.3). Any context, immutable.

Enums

UsbDescriptorType

Descriptor types (USB 2.0 section 9.4 table 9-5, hub class section 11.23.2.1, USB 3.2 table 9-6 and section 10.15.2.1).

UsbEndpointType

Transfer type of an endpoint, from bmAttributes bits 1:0.

UsbRequestType

bmRequestType of a setup packet (USB 2.0 section 9.3.1): one direction, one type and one recipient, OR-ed together.

UsbSpeed

Bus speed of a USB device. The values are the xHCI default Protocol Speed IDs (xHCI 1.2 section 7.2.2.1.1), which is what a root port reports and what a Slot Context takes; another host controller translates its own numbering to these.

UsbStandardRequest

Standard request codes (USB 2.0 section 9.4 table 9-4). Hub-class requests reuse the same codes with a class request type (section 11.24.2); requests only one class defines live with that class driver.

UsbTransferStatus

Outcome of a synchronous USB transfer, independent of the host controller that carried it.

Delegates

UsbReportHandler

Receives one completed transfer of an interrupt IN pipe. Interrupt context, under no lock, on a controller with a message interrupt; on a polled one, thread context on whichever thread drains the controller's events (its hot-plug thread, or any thread waiting on one of its commands or transfers), under the host's own DeviceLock; the span is valid for the call only; the handler must not block, allocate, or call any UsbAccess or DeviceBinding member; it may call a sink and Signal(), and may use Interlocked on its own fields.
