抢占

抢占式调度器可以在正在运行的线程不配合的情况下，把 CPU 从它手中拿走。硬件中断（通常是定时器节拍）无论线程当时在做什么，都会把控制权转交给内核，内核随后可以自由地改为恢复另一个线程的运行。另一种做法是协作式调度（cooperative scheduling）：只有当正在运行的线程通过让出或阻塞而主动交出 CPU 时，才会发生切换；在这种模式下，一个从不让出的线程会永远占据 CPU，一个有 bug 的循环就会让整个系统冻结。

抢占把 CPU 时间变成一种由内核分配的资源，而不是由线程自行夺取的资源。节拍周期限定了任何线程能够独占一个核心的时长（即它的时间片），因此一个无限循环只会白白耗掉它那一份 CPU 时间，而不会让系统卡死。代价由每个线程承担：由于节拍落在任意一个指令边界上，代码可能在任意两条指令之间失去 CPU，因此必须相应地保护自己的临界区，手段是屏蔽中断或使用原子指令。

在 Cosmos 内核中，目前每一次上下文切换都是抢占式的：切换发生在中断退出时（10 ms 的节拍、处理程序唤醒了另一个线程的设备中断，或者正在阻塞的线程在自己的 CPU 上触发的中断），除此之外，线程会一直运行，直到它在某个阻塞原语上挂起或退出；还不存在可用的主动切换。参见抢占和不存在的东西：主动切换。
