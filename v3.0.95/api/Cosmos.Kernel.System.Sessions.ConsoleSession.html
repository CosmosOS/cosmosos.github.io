One console that Console can be bound to: a screen, and the keys typed at it. The local virtual consoles and the connections of a remote terminal server, such as the Cosmos.Network.Telnet package's, are all sessions. SessionManager numbers them, shows one of them on the display, and binds every thread to one, so the same Console calls read and write whichever session the calling thread belongs to.

Remarks

Every session keeps its screen as a KernelConsole grid, on the display's canvas but hidden until the session is shown, so a session can be switched to at any time, a remote one included. Output runs with interrupts masked, so the screen and a remote terminal see one thread's changes in the order it made them.

A library adds a remote session by deriving from this class: the ConsoleSession(int, int) constructor gives it a screen, EnqueueInput(KeyEvent) takes the keys its terminal sends, and the On hooks tell it every change to send there. The hooks that report a change run inside it, with interrupts masked: they record what changed and return, without blocking, waiting or doing I/O. Only OnFlush() and OnClosed() run unmasked.
