IVfsDirectoryHandle

Managed handle for a directory node supporting lookup and mutation operations.

IVfsFileHandle

Managed handle for an open file with position and byte I/O. Disposal is the one state the two halves of this interface report differently: every Try member answers false for a disposed handle, because that is what its bool already means, while Read(Span<byte>) and Write(ReadOnlySpan<byte>) throw, having no count that means "the handle is gone" rather than "no bytes moved".

IVfsFileSystemType

Registered filesystem driver entry point.

IVfsFormatOptions

Marker for filesystem-specific format parameters. Each driver casts to its own concrete type (e.g. FatFormatOptions); a null value means "use driver defaults."

IVfsInode

Single inode (any type: file, directory, symlink, etc.).

IVfsNodeHandle

Common surface for VFS nodes (files or directories). The interface is disposable so both handle kinds work in using blocks, but only a file handle has anything to release: it owns the open-file state the driver keeps for a read or write position. Disposing a directory handle does nothing, and a directory handle stays usable afterwards.

IVfsOpenFile

Per-open file state (position, etc.).

IVfsSuperblock

Per-mount filesystem instance.
