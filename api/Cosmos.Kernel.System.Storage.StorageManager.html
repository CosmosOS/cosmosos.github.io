Class StorageManager

Namespace
Cosmos.Kernel.System.Storage
Assembly
Cosmos.Kernel.System.dll

Manages block storage devices. A disk reaches the manager one of two ways: a driver kit driver publishes it and the manager's Cosmos.Kernel.System.Storage.KitBlockConsumer registers it (the AHCI, NVMe, virtio-blk and USB mass storage drivers), or it is handed to RegisterDevice(IBlockDevice) directly by the kernel. Every registration scans the disk for partitions. The tables change after boot too, when a USB disk, or a virtio-blk disk behind a PCI Express hot-plug slot, is plugged in or pulled out, from the kit worker in a probe or a teardown: each is replaced whole on every change, so a list read from Devices, Partitions or GetPartitions(IBlockDevice) never changes under its reader. Read it once and index that copy: a second read may be a newer table.

The tables are kept in one order, which decides the primary device: a kit disk before a hand-registered one; among kit disks the smaller node path by ordinal comparison (pci: before usb: before virtio:), and among equal paths the earlier registered; among hand-registered disks the earlier registered. So an internal disk on a PCI controller comes before a USB stick present at boot whichever registered first, and a kit disk arriving after a USB stick moves ahead of it and renumbers Partitions, which is why a mount by Partition keeps its partition where a mount by index string keeps its index.

GetPartitions(IBlockDevice)

The partitions discovered on one device, in on-disk order, so a kernel can number them per disk the way a user does. A partition's position in this list is its index on device. Empty when the device has no partition table or is not registered. Allocation-free: the list is the entry's own array, replaced whole by a rescan, so a caller's copy never changes under it.

RegisterDevice(IBlockDevice)

Registers a block device with the manager and scans it for a GPT or MBR partition table. Discovered partitions are appended to Partitions. A device already registered, or one more than the manager holds, is silently ignored. Thread context: the boot thread or a kernel's own thread; the scan reads the disk before the lock.

RescanPartitions(IBlockDevice)

Re-scan a previously-registered device for a partition table. Existing partitions belonging to that host are dropped first, so callers that just wrote a new layout (tests, formatting tools) get a clean partition list. The device keeps its place in Devices. Thread context: a kernel's own thread or a test; the scan reads the disk before the lock.
